"我做了一个 AI 备考平台，核心差异化是**个人知识库 RAG**——学生上传自己的笔记，AI 在答疑和错题诊断时精准引用笔记内容，而不是给通用答案。技术栈用 Java 21 虚拟线程驱动 DAG 引擎实现三路并行错题诊断，Milvus per-tenant Collection 做个人笔记向量检索，RRF 三路融合重排，语义缓存把响应时间从 10 秒降到 50 毫秒。SkyWalking 做了三个通用 APM 覆盖不了的深度定制。全链路可演示。"

## 技术故事一：个人知识库 RAG（最核心的差异化）

> **面试场景**：自我介绍后第一个深入话题

"这个项目跟通用 AI 答疑工具最大的区别是——AI 不是从互联网找答案，而是从学生自己的笔记里找。

每个用户有独立的 Milvus Collection。笔记上传后按章节标题自动切分——不是按固定 500 字切，是按知识点边界切——然后 Embedding 向量化入库。答疑时三路并发检索：个人笔记向量检索、真题库 HNSW 索引、PostgreSQL GIN 全文检索，三路结果用 RRF 倒数排名融合重排，取 Top-10 注入 System Prompt。

AI 回答末尾自动生成 noteRefs 引用卡片——"根据你《高等数学上册》第 2 章笔记，极限求解的核心步骤是..."。学生看到的是 AI 读懂了他的笔记，而不是泛泛而谈。

**面试追问准备**：
- 为什么 per-user Collection 而不是 tenant_id 过滤？→ 笔记语义空间独立，混合检索精度下降 15-20%
- 按知识点切分怎么实现？→ 标题层级检测 + 最小 chunk 长度过滤，不是固定窗口
- embedding 模型选的什么？→ 火山方舟 doubao-embedding-vision-250615，2048 维

## 技术故事二：DAG 三路并行错题诊断 + 虚拟线程

> **面试场景**："最有技术深度的模块"

"我手写了一个 DAG 工作流引擎。核心是 Kahn 拓扑排序——错题诊断拆成三个 AI 节点：前置考点漏缺分析、核心公式混淆分析、计算步骤失误分析。拓扑排序识别出三个节点互不依赖，放在同一层用虚拟线程并发执行。

为什么选虚拟线程？LLM 调用是典型的 I/O 密集型场景——每次调用等 3-10 秒。平台线程池 200 个线程撑不住 1000 并发，P99 直接飙到 35 秒。虚拟线程遇到 I/O 阻塞自动让出 Carrier Thread，1000 并发下 P99 稳定在 10 秒以内，内存只有平台线程的 1/4。

三个诊断节点的等待时间完全重叠——用户看到的是三路 AI 同时思考、同时输出。诊断结果通过 SSE 逐字流式推送，每个 chunk 带 nodeId 标签，前端三栏同步展示。

**面试追问准备**：
- 怎么处理节点失败？→ CompletableFuture.orTimeout(180s) + try-catch 隔离，单节点失败不影响同层
- 图有环怎么办？→ DagGraph.validate() 用 DFS 三色标记法检测环路，抛 DagCycleException
- 怎么验证并行执行？→ 日志时间戳重叠 + JMH 基准测试数据

## 技术故事三：语义缓存 + RRF 多路融合

> **面试场景**："性能优化做了什么"

"做了两层优化。

第一层是语义缓存。学生经常问相似的问题——'闭区间最值怎么求'和'闭区间上怎么找最值'本质是同一个问题。我把问题 Embedding 后查 Milvus 相似度——但不是用相似度做缓存命中判断，那太慢了——而是先用 Redis 做快速缓存（MD5 精确匹配），未命中才走 Milvus 相似度。缓存命中后响应时间从 10 秒降到 50 毫秒，Token 消耗减少 90%。相似度阈值 0.96 不是拍脑袋的，我跑了 4 组对比实验。

第二层是 RRF 三路融合。单靠向量检索有语义漂移——'求极限'可能召回'求极值'。加了 PostgreSQL 全文检索做关键词锚定，两路结果用 RRF 融合（k=60），召回精度提升明显。

**面试追问准备**：
- 阈值 0.96 怎么定的？→ 0.90/0.93/0.96/0.98 四组实验，0.96 是命中率和误命中率的最优平衡
- 为什么不用纯 Milvus 相似度做缓存？→ 每次查 Milvus 延迟 20-50ms，Redis 不到 1ms

## 技术故事五：多租户算力隔离 + SkyWalking 深度定制

> **面试场景**："怎么保证服务质量"

"多租户隔离的核心思路是——限的不是 HTTP 请求，是 LLM Token 算力。一个学校查 100 次历史记录（Redis 10ms）和一个学校 5 个并发 LLM 诊断（10 秒 GPU），成本完全不同。

我用 JVM Semaphore 做租户级并发配额——每个 userId 绑定一个信号量，默认 5 并发。信号量耗尽返回 429。配额可通过管理接口动态调整。

SkyWalking 我做了三个通用 APM 覆盖不了的定制：

1. **FTT 首字延迟埋点**——通用 APM 只能看到 SSE 流的总耗时 30 秒，我在 onMessage 首帧回调中手动创建 Span 并关闭，精准捕获学生体感的关键指标——第一个字出来前的 1.1 秒。
2. **跨 RocketMQ Trace 传播**——刷题行为异步上报的链路（Web → MQ → Consumer → PostgreSQL），通过消息头注入 TraceContext 实现全链路串联。
3. **Noisy Neighbor 检测**——结合 SkyWalking Profile 虚拟线程堆栈采样和 Semaphore 等待队列，2 分钟内定位恶意抢占的租户。

**面试追问准备**：
- 为什么不在网关限流？→ 网关只能限 HTTP QPS，无法区分 10ms 的 Redis 请求和 10s 的 LLM 请求
- FTT 数据怎么驱动优化？→ FTT 数据直接推动了语义缓存的优先级——"哪些问题应该预缓存"由 FTT 分布决定

## 常见面试追问速答

| 问题 | 回答要点 |
|------|---------|
| 为什么选 Java 21？ | 虚拟线程是 I/O 密集型场景的最佳解，LLM 调用是典型 I/O 密集型 |
| Milvus vs pgvector？ | Milvus HNSW 索引 1M+ 向量仍保持 <20ms，pgvector 适合小规模 |
| 为什么不用 Spring Cloud？ | 1 人项目微服务是负优化，面试会被追问分布式事务 |
| DAG 引擎和 Temporal/Argo 的区别？ | 它们是通用编排引擎，我的是教育领域专用——节点类型固定、超时策略定制、SSE 流式回调耦合 |
| 最难的技术决策？ | 语义缓存阈值选定——0.90 误命中率太高，0.98 命中率太低，跑实验找到 0.96 |
| 如果重来会怎么改？ | 笔记 OCR 接入应该更早做——印刷体效果好，手写 OCR 才是真正的高频场景 |
